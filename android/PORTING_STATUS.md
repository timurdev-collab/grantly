# EduT Android port status

Updated: 2026-10-25. Source branch: `feature/android-compose-foundation`.
Design and behavior reference (read-only): `design/home-concept-02`.

## Implemented in Android source
- Compose home layout and bottom navigation.
- Read-only scholarship discovery through the existing public Supabase RPC.
- Server-side search, degree/country/field/funding filters, sorting and pagination.
- Scholarship detail tabs for overview, eligibility, benefits and application information.
- Profile-tab email/password sign-in, signup and sign-out through the existing Supabase Auth API.
- Authenticated Applications list showing saved scholarships, status and notes (first 100).
- Authenticated application status and notes editing through existing user-scoped APIs.
- Application task checklist: read, complete/reopen, add custom tasks, confirm before deleting custom tasks, and set/change/clear task due dates using existing `application_tasks` RLS table (not yet device-tested; first 100 tasks per scholarship). Due dates use the existing `due_at` timestamptz column, store the selected day at local noon and display in the device time zone; travel/time-zone changes may alter the displayed calendar day. No reminder notifications are scheduled.
- Personal application target dates can now be viewed, selected using the native Android date picker, changed or cleared from saved scholarship cards. Writes are scoped to the signed-in user's `saved_scholarships` row and use the existing `personal_deadline` date column under RLS. This does not change official provider deadlines, does not send Android reminders and remains unverified with a live account/device.
- Private application document metadata, single-file uploads and confirmed deletion via the existing user-scoped RLS table and private Storage bucket (PDF/JPEG/PNG/HEIC/HEIF, up to 6 MiB). Upload failure attempts storage rollback; all mutations remain unverified on a live account/device.
- Save/remove scholarship controls on detail screens using existing user-scoped Supabase RLS policies (not yet device-tested).
- Automatic access-token refresh and Android Keystore AES-GCM encrypted session persistence, including restoration at launch and local token removal on sign-out (not yet device-tested).
- Password recovery email requests, verified recovery deep links and password update through the existing Supabase Auth API (not yet device-tested).
- Private academic profile summary and validated editing through the existing `student_profiles` RLS table; degree, GPA, IELTS, graduation, residence, nationality, major and study preferences. Role is read-only and never included in update payloads (not yet account/device-tested).
- Read-only approved advisor directory, reachable from the Home guidance card after sign-in. Uses existing authenticated `available_advisors` RPC, with local search and advisor detail summaries (not yet live-account/device-tested).
- Read-only advisor consultation service options (duration, live price and discount) and authenticated consultation-request history (status, advisor, topic and quoted price), using existing `available_advisor_services` and `my_advisor_consultation_requests` RPCs (not yet live-account/device-tested).
- Personalized scholarship recommendations through the existing `get_my_scholarship_matches` RPC, including ranking, explanations and eligibility warnings (not yet live-account/device-tested).
- Advisor consultation booking requests using the existing policy-acceptance and booking RPCs. Displays three policies, records versioned consent, allows service and local preferred date/time selection, and sends the chosen instant in UTC with the device time zone. No in-app payment or guaranteed booking; requires live-account/device testing.
- Read-only authenticated Community feed reachable from Home, loading visible non-story posts in 30-post pages through existing social_posts RLS with manual refresh, explicit Load more, caption and media-presence indicators. Pagination preserves already loaded posts and deduplicates by post ID. Community post comments now support viewing the first 100 visible comments, writing a 1–1,000 character comment, and deleting your own comments with confirmation through existing RLS policies. Community now includes like/unlike controls using existing social_post_likes RLS, with batched lookup of the signed-in user's likes, per-post busy states and error recovery. Text-only post creation (1–2,000 characters) now uses the existing social_posts insert policy; publishing is denied by the server unless the author has a visible Community profile. Own text-only Community posts can now be edited (caption only, 1–2,000 characters) and deleted after confirmation using user-ID-scoped, kind-scoped and media-null-scoped PATCH/DELETE under existing RLS. The feed also checks legacy media_url when identifying media, so media posts cannot accidentally be edited or deleted without Storage cleanup. Private Community photo preview is now wired to the feed for posts with an image media_path: Android requests a one-hour signed URL from the existing private social-media Storage bucket, checks the Supabase host, rejects redirects and oversized images, and downsamples decoded bitmaps. This read-only photo flow is not yet live-account/device-tested and does not handle legacy media_url. A read-only private Community video preview now downloads supported MP4/MOV/M4V media_path clips to app-private temporary cache with a 200 MiB limit, signed Storage URLs, strict same-host checks and no redirect following; Android VideoView plays the local file and cleanup runs on exit. The video flow is not yet live-account/device-tested, may reject large videos and does not support legacy media_url, uploads, stories or community profile editing; no author cards; hidden community profiles may yield an empty feed. Community post reporting is now available for other authors' visible posts, using the existing RLS-protected `social_post_reports` insert policy and iOS-equivalent reason choices (one report per reporter/post). Feed actions are horizontally scrollable on narrow screens. Community, comment, like, text-post creation, editing, deletion and post-report mutations have not been account/device-tested.
- Single-photo Community publishing (JPEG/PNG, up to 6 MiB) now uses a bounded Android document picker, magic-byte checks, image-dimension validation, existing private `social-media` Storage upload permissions and `social_posts` insert RLS. A preflight visible-profile check avoids uploading for accounts whose Community profiles are hidden; failed post inserts attempt private Storage rollback. No backend changes. This path has **not** been authenticated-account/device-tested and does not support HEIC, video uploads, stories, or media-post deletion.\n- Community posting access now performs a read-only authenticated lookup of the signed-in account's existing community_profiles.is_visible flag. The Create post button is disabled when the profile is hidden, absent, or the lookup fails; transient lookup errors offer a retry. This does not unhide profiles, change the iOS 1.0 release policy, or bypass server RLS. The eligibility check and posting flows still require real-account/device verification.
- Advisor-only Messages tab with authenticated conversation summaries, unread counts, paginated messages, manual refresh, read receipts and explicit message sending. Approved advisor profiles can open or create advisor-direct conversations through the existing role-restricted RPC. Foreground-only inbox polling (30 seconds) and thread polling (20 seconds) now refresh content while visible; thread updates preserve older paginated messages. Android includes user/message safety reports and block/unblock controls through existing RLS-protected tables, including a block confirmation and disabled composer for locally blocked users. Polling is not a realtime subscription or push notification; messaging and safety actions are not live-account/device-tested.

## Preview safety
Authentication tokens are stored as AES-GCM ciphertext using a non-exportable Android
Keystore key; app backup is disabled. On restart, the app attempts to restore and refresh
the encrypted session. Sign-out clears local credentials before contacting the server.
If Keystore storage is unavailable, the app keeps an in-memory session only. The
persistence flow has not yet been verified on a physical Android device.

The iOS `design/home-concept-02` HomeView currently emphasizes scholarship matches, deadlines and advisors; Android's Community shortcut is an additional preview entry point, not verified iOS Home visual parity.

A successful `Android Debug APK` GitHub Actions build proves compilation only, not
feature parity, server availability, account behavior or device compatibility.
Do not distribute the debug APK as a production release.
